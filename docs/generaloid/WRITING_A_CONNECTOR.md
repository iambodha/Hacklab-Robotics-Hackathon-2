# Write a connector: the SO-101 example

A third robot should require a connector, not server branches. Built-ins are discovered from packages under `generaloid/connectors/`; external packages work through `--connector mypackage.myrobot:CONNECTOR`. Do not edit the registry or server for each robot.

1. **Identify the source of calibration.** SO-101 reads `sim/robots/so101.json` through `ProfileConnector`. This supplies motor IDs/names, physical gripper width, camera identifiers and safety/motion settings. Start with a new profile or implement the declaration properties directly. Avoid copying real calibration values into server code. Set `hardware_verified=False` until qualification is complete.

2. **Declare the joint and gripper mapping.** See `So101Connector` in `generaloid/connectors/so101/__init__.py`. Its five arm joints precede one gripper joint; IDs match Station's bus. Model actuator order must match the declaration, with arm actuators first and gripper last. MCP joint targets are normalized calibrated positions; gripper 1 means open. SO-101's upper model limit is open, while ElRobot's is closed. The real profile also declares ticks-to-angle zero points and signs; checking only the simulation does not validate those.

3. **Declare cameras, frame and safety.** Provide wrist/overview roles, twin camera names, Station identifiers, image dimensions and `SafetyEnvelope`. Hardware queue IDs may be unset only while unqualified. `frame_text` describes the twin's base coordinates; override `frame_for(mode)` if a legacy real backend differs. SO-101 currently does this explicitly: twin +y ahead, real +x ahead. A production connector should calibrate a single frame or implement a tested transformation before sim-to-real use.

4. **Build a twin model.** `so101/scene.py` imports NormaCore's follower URDF and meshes. It ports the geometry adjustments from `origin/simulation_s101` without modifying `sim/build_scene.py`. The builder adds actuators, limited gripper torque, jaw contact pads, `grasp_tcp`, wrist camera, scene objects and a rest keyframe. The TCP site's +y points out of the fingertips and +x follows the jaw closing axis. Bundle a small layout and camera pose beside the connector. `TwinSpec.build_scene(out_dir)` must return a valid MuJoCo XML path; generated files belong outside source control. Rebuild after changing model sources.

5. **Supply kinematics.** `make_ik(model)` returns the connector's IK on the mounted twin. SO-101 uses `GenericIK` with a looser rotation tolerance for a five-axis arm. `kinematics()` offers the same FK/least-lean interface for independent checks. `reach_probe()` names a point known to be reachable jaws-down. Test several workspace points before increasing the safety envelope.

6. **Declare actual skills per mode.** SO-101 sim supports `MOTION_SKILLS`, `skill_config` and `operator_reset_scene`. It composes picks from motion primitives; it does not expose the ElRobot bottle-twist skill. Real support reuses the existing profile-driven server and conservatively advertises motion, pick, drop and survey. A legacy server may expose more tools than the connector's qualified skill set: metadata is capability guidance, not tool filtering. Do not claim a skill merely because another robot has its implementation.

7. **Implement `mount(mode, station)`.** In sim, call `mount_generic(self, output_directory)` and return `Mount(..., tools=server, robot=twin, close=twin.close)`. In real mode, use only the supplied Station adapter; never open a serial port or camera yourself. For existing legacy real tools use `core.legacy.real_tools(profile_name)` followed by `station.install()`. Real importing must be lazy with respect to network I/O. The fake Station must be sufficient to exercise motor tools. New connectors can implement their own tools while retaining the same Station contract.

8. **Export the object.** Put `CONNECTOR = So101Connector()` in the package's `__init__.py`. `connectors.available()` discovers it automatically. For a built-in, run the unchanged parametrized `test_connector_contract.py`; for an external connector, use the same assertions with your exported object. The base test vocabulary describes current skills; extend shared vocabulary deliberately if introducing a new skill.

9. **Validate offline.** Run `describe`, `tools --mode sim`, FK/IK tests, the fake Station test, and `generaloid.checks pick --connector so101` over MCP stdio. Confirm refusal behaviour for out-of-envelope and oversized moves. Use one connector per process. Run hardware qualification only later, with a separately authorized operator, completing all profile `_to_verify` fields first.

Optional communications need no connector-specific wiring. The server calls `generaloid.comms.register(server, connector)` after mounting when the module exists. Public connector metadata is the add-on's input; an absent comms module must never prevent serving robot tools.
